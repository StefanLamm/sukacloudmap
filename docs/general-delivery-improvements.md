## 被拒绝性能实现与功能保留边界

`fragment_merging` 是未获正式采用的性能开关，功能保留版日常关闭。实验实现从当前输入按仓、完整兼容报价及当前车辆容量生成有向开口线路 fragment。坐标只决定探索顺序，成本与时间来自实测有向道路；fragment 的亏损前缀仍能参与后续合并，不按城市强制拆分。它提交当前核价提案，不把 fragment 当作已经占用的实际车。后续物理组合和完整实际 proof 才能更新方案。

`complete_assignment_pricing` 同样不纳入功能保留版日常默认。实验实现每次原生求解返回 Python 后，优先紧凑核价完整 `best_specs`，不受普通候选池容量限制。实际必送线路保留；可选线路按真实专车和共配机会成本过滤，再由原 host 整单证明或一次全局物理选择决定是否接受。原生模型代理目标不会成为报价。该通道在原 allowance 内为核价预留最多 0.5 秒、至多 15%；没有单独增加预算。

`joint_reoptimization`、`scalable_joint_search` 和 `stage_budget_reservation` 的接口仍可用于独立实验，但最终候选日常默认均关闭。联合接口可解冻 2～4 条相关整线、共配任务和空闲实际车，可扩展邻域也覆盖超过七店的大组，不按城市强制拆分，允许增减实际车；只有整单完整实际费用严格下降才接受。生产政策开发补核中，联合整体开关通过其条件性门槛，但可扩展实现及时间预留未通过完整依赖链门槛，因此没有把这组能力纳入最终日常默认，也不宣称已经完成第三阶段的日常收益验收。

`critical_edge_collection` 日常开启，在生产道路适配器上补采有潜力组合的必要有向连接，阶段时间份额结束后允许后续主搜索及最终复核继续按需查询；这是阶段时间分配，不是 API 总次数额度。冻结图实验明确跳过网络补采，不用估算边冒充实路。诊断与关键缺边补采属于用户要求的功能政策，不能用固定图无 HTTP 实验冒充其独立降费证明。

整票不拆、固定出货仓、实际车一天一趟、容量、营业时窗及跨日营业、等待与卸货、报价兼容、附加费和不计返仓继续由当前真实输入与核价/审计执行。历史提示只提供当前身份与顺序提案，旧归属、费用和输入不直接继承。
