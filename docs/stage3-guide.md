# 第三阶段：基础资料与报价

> 第四阶段业务现已实现，最新使用方式见 [每日需求与规划输入说明](stage4-guide.md)。

> 2026-11-11界面调整：四个管理页已取消业务日期、当日安排和兼容判断入口，相关操作统一迁入「物流线路规划」。位置选择已支持开放地图、拖拽与文字搜索。以下S3规则中的版本日期、最晚到店仍保留在兼容接口与旧数据中；当前页面和新模板以 [最新调整说明](ui-revision-guide.md) 为准。

本阶段对应交接方案 S3。所有登录人员共用仓库、门店、车辆和报价；管理账号与操作记录仍仅管理员可用。页面支持新增、查询、分页、编辑及xlsx批量新增或更新。基础资料不提供删除，避免引用资料丢失。

## 推荐录入顺序

1. 仓库：编号、名称、地址、默认最早发车时间。
2. 报价方案：稳定编号、名称、计费模式、完整参数、生效日期。
3. 门店：稳定编号、名称、地址、出货仓、营业时间、卸货时长，再配置专车报价和共配单价。
4. 车辆：完整车牌、默认归仓、最大件数、可用性，再补货车道路资料。
5. 选择配送日期，维护当天的仓库发车时间和车辆归仓、可用性。

城市仅作资料与搜索字段。可按城市命名复用的报价模板，但门店必须明确引用报价，不根据城市或名称猜测、自动换价。改变城市不改变既有报价引用。

## 字段与校验

| 资料 | 必填 | 可选及规则 |
| --- | --- | --- |
| 仓库 | 编号、名称、地址、最早发车时间 | 经度、纬度、坐标系、位置来源 |
| 门店 | 编号、名称、地址、出货仓、营业开始/结束、卸货分钟数 | 城市、明确跨日标记、最晚到店日期时间、专车报价、共配每件价、定位资料 |
| 车辆 | 完整车牌、归属仓、最大件数 | 默认可用；货车车型大小、动力类型、车牌颜色、长宽高、核定载重、满载总重、轴数 |
| 报价 | 编号、名称、模式 | 按模式填写全部计费参数；生效日期用于选择有效版本 |

编号为1至40位字母、数字、点、下划线或短横线，以字母或数字开头，统一转大写；创建后不可改。仓库、门店及报价编号分别唯一，名称允许重复。车辆按去除空白和间隔点、转大写后的完整车牌校验唯一；使用中国普通、新能源及常见挂/学/警/港澳车牌格式。

最大件数为正整数；卸货分钟数、包含门店数为非负整数，不接受小数或布尔值。件数只限制装载件数，不推算吨位，不产生车型加价或续航约束。货车尺寸单位为米，重量为吨，满载总重不能小于核定载重。

时间使用北京时间和严格的 `HH:MM` 格式。同日闭店必须晚于营业开始；跨日需要明确选择次日闭店，不能只靠小于开店时刻来推断。最晚到店为带日期的实际到店限制，页面按北京时间录入；接口必须提供时区，例如 `2026-11-12T01:30:00+08:00`。本阶段保存限制，实际行驶、等待、卸货时序在 S5 实现。

经纬度必须成对提供；填写坐标时必须明确 `GCJ02`、`WGS84` 或 `BD09`，同时记录来源。经度范围[-180,180]、纬度[-90,90]，最多8位小数。可暂不定位。页面「选择位置」可搜索地点、点击选点和拖拽标记，也可手工修改坐标；已关联位置可在地图显示。WGS84/GCJ02/BD09之间的展示适配已提供，真实货车道路及正式算路转换留待 S5。缺定位、待转换、缺货车参数会明确标记，资料齐全也只表示待算路，不表示道路已通过。

## 报价、空值与版本

金额使用精确十进制值，非负，最多18位数字、6位小数；推荐Excel按文本填写以免被表格软件舍入。`2`、`2.0`、`2.000` 规范化后相同，`0` 是有效零价，空白/NULL是未配置。

| 模式 | 必须填写的有效参数 | 后续计费公式 |
| --- | --- | --- |
| 按公里 `KM` | 每公里单价 | 实际货车线路公里数 × 每公里单价 |
| 起送加串店 `BASE_STOPS` | 起送价、包含门店数、串店费 | 起送价 + max(门店数 − 包含门店数, 0) × 串店费 |

不接受另一模式的非空参数，防止混用。门店可只配一种运输方式：缺专车报价不影响已配置的共配，缺共配单价不影响专车配置；两项都缺则分别提示。新建报价方案本身必须填写该模式的完整参数。

修改报价名称、参数、模式或生效日期会新增只读版本；完全相同的更新不制造新版本。所选配送日期使用已生效日期中最近的一份，同日多版本取版本号最高者。未来生效版本不会提前改变当前价。旧版本保留；规划输入和历史方案快照由 S4/S7 实现，本阶段尚未生成配送方案。

在「物流线路规划」门店列表勾选多店后可判断兼容。必须同时满足同一出货仓、同一计费模式、每个有效参数完全一致。城市、报价名称/编号、车辆容量不参与报价签名。输出各兼容组及不兼容原因；此结果只判断报价条件，容量、可用车辆、时间和真实道路仍需后续验证。不会自动挑选便宜方案或改写门店报价。

## 当日安排

「物流线路规划」显示明确的配送日期，四个管理页面不再提供日期选择。仓库默认发车时间和车辆默认归仓/可用性可单独编辑；「当日安排」只作用于所选日期。未单独设置时沿用默认，已单独设置的日期不随默认资料修改。编辑当日安排使用独立修订号，避免覆盖其他人的更新。

## 批量导入

四个页面均提供对应xlsx模板。只在「数据」工作表填写，第一行为固定中文表头，也支持接口字段名；「说明」页给出格式和单位。可仅保留单一数据页，多个工作表时只能包含「数据」和「说明」。不接受CSV、旧xls、公式、错误单元格、宏或外部链接。

| 模板 | 必填列 |
| --- | --- |
| 仓库 | 仓库编号、仓库名称、地址、最早发车时间 |
| 门店 | 门店编号、门店名称、地址、出货仓编号、营业开始、营业结束、闭店跨日天数、卸货分钟数 |
| 车辆 | 车牌、归属仓编号、最大件数、默认可用 |
| 报价 | 报价编号、方案名称、计费模式；计费参数按模式必填，当前模板不要求日期 |

编号必须使用文本单元格，保留 `0001` 等前导零。关联仓库与报价只按编号匹配，必须事先存在；不以重名或城市自动匹配。同文件出现重复编号或车牌报错，不能用后行静默覆盖。

车辆默认可用填「是/否」；车型大小为1微型、2轻型、3中型、4重型；车辆类型为0普通、1纯电、2插混；车牌颜色可使用模板中文选项。闭店跨日天数填0或1。坐标系、位置来源及计费模式遵照模板说明。

上传先预览，展示新增/更新数量、来源行、错误字段；预览本身只保存批次，不改基础资料。任何一行有错误，确认整批导入按钮不可用，接口也拒绝提交。全部通过后才可一次提交；事务中途出错则整批回滚。

已有资料按编号或车牌整行更新，稳定ID保留；空白可选业务字段会清空原值，不删除文件未包含的资料。空白城市保存为空，未提供的位置来源记为Excel导入，无坐标时坐标系标签默认GCJ02；有坐标但未明确坐标系会报错。导入默认车辆资料不覆盖既有的当日安排。

预览与提交之间若任何基础资料或当日安排发生变化，提交返回409，需重新上传预览；账号操作或共享记录编辑不影响基础资料预览。预览有效24小时，重复确认已提交批次返回原回执，不重复新增。每批最多5MiB、10000个非空数据行，另有解压体积和稀疏工作表保护；这些是单批技术限制，不是800家门店或50辆车的业务上限。

这是基础资料导入。每日件数、重复需求聚合及按配送日替换需求属于 S4，尚未实现。

## 接口契约

所有接口要求现有登录会话，写请求要求 `X-CSRF-Token`。校验失败返回422及字段详情；编号重复、修订冲突、预览过期或失效返回409。错误不会回显原始提交值。四类资料的 `kind` 为 `warehouses`、`stores`、`vehicles`、`quotes`。

- `GET /api/master-data/catalog?delivery_date=2026-11-11`：按日期读取全部主资料及当日有效值。
- `GET/POST /api/{kind}`：列表或新增；`GET/PATCH /api/{kind}/{id}`：详情或部分更新。更新必须带当前 `expected_revision`。
- `PUT /api/{warehouses|vehicles}/{id}/days/{date}`：更新当日安排。新设置修订号为0，已有设置用 `day_revision`。
- `GET /api/quotes/{id}/versions`：读取完整只读版本列表。
- `POST /api/master-data/compatibility`：请求 `store_ids` 数组和 `delivery_date`，返回兼容组、原因和验证边界。
- `GET /api/master-data/templates/{kind}.xlsx`：下载模板。
- `POST /api/master-data/imports/{kind}/preview?filename=example.xlsx`：请求体直接传xlsx字节，类型 `application/vnd.openxmlformats-officedocument.spreadsheetml.sheet`，非multipart。
- `GET /api/master-data/imports/{preview_id}`：查看预览状态和错误。
- `POST /api/master-data/imports/{preview_id}/commit`：事务确认，返回新增/更新/未变更回执。

本地SQLite和浏览器已验证，详见 `stage3-validation.json`。目标PostgreSQL、真实地图权限及正式部署仍需后续环境验证。
