# 第五至八阶段本地使用说明

版本：v0.15.0；日期：2026-11-13。日常规划已接入多轮多种子、跨轮线路汇总、CP-SAT联合选优及高德普通驾车道路复核，使用本地SQLite和现有网站入口。真实货车道路、PostgreSQL及正式部署仍按目标环境另行验收；普通驾车参考草稿不能标为已核验的货车执行方案。各轮历史阶段说明与本次真实新分组验收见 [最新功能与验收](latest-improvements.md)。

## 每日业务操作

所有业务仍在「物流线路规划」。仓库、门店、车辆、报价页面只维护基础资料。

1. 选择配送日期，新建或选择需求分组，在组内创建需求或导入每日件数。导入只替换当前分组。核对当日仓库发车、车辆归仓/可用性和门店收货限制，再冻结输入快照。
2. 打开「方案规划与调整」，点击「开始规划」。默认优化时限为300秒，可调整到1至24000秒。任务自动完成多轮多种子搜索、跨轮候选汇总、CP-SAT联合选优及最终道路复核，页面显示阶段进度；网络等待另计并有整体上限。后台任务可取消，期间可查看其他物流子板块。只追加完整合法方案；未找到完整可行结果时明确报错并保留输入与历史，不能据此宣布业务无解。
3. 查看专车线路、逐店到店/等待/卸货/离店时间、共配与费用。共配不执行专车到店时间限制。真实驾车入口自动采集本轮道路；发现迟到等冲突时比较修复方案，已采路段固定复用，仅补采新连接，保存本轮找到的最低费用可行草稿。无法完成道路或费用复核时，不沿用旧低价伪装成功。
4. 「人工调整」可逐店选共配、未分配或实际车辆；用上移/下移改顺序。重算保存新草稿，不自动修复或丢弃冲突选择。费用不完整时只展示已核算金额；可比较时展示相对原方案的增减额。改动尚未重算时，费用和地图仍属于上次结果。
5. 只有当前输入、最新版本、独立复核通过、无未分配且所有专车道路满足真实验证条件的方案才能确认。确认生成新的只读版本；全共配无需专车道路。
6. 历史版本保留冻结输入、计费与时序、道路证据及摘要。基础资料或需求变化不会修改历史费用；可恢复旧版为新草稿，旧输入仍不能绕过当前输入检查。
7. 导出 Excel 或证据 JSON 时，始终导出正在查看的版本。Excel 包含版本汇总、专车线路、逐店分配、共配费用、异常、道路证据六个表；金额为保留两位小数的十进制文本。所有字符串按文本写入，避免门店名触发公式。

离开整个规划页面前请先重算保存。浏览器刷新会丢失尚未提交的人工选择，并有离开提示；已保存草稿、方案与任务状态保存在数据库中。

## 固定道路演练

右侧提供「混合配送·预期56元」「车辆共享·预期40元」。固定样例可以改车、方式和顺序并重算，不写入业务主数据、每日需求或历史方案，也不能确认执行。样例没有真实坐标与折线，地图明确显示说明，不绘制假道路。

56元样例：V10按A→B，8公里、10件、专车16元；C/D共配40元。40元样例：SMALL服务A、LARGE服务B，分别20元。同仓和完整计费参数分组，不按城市或报价名称硬分；所有组共享同一实际车辆池。

## 计算与搜索边界

公里费用按实际路段米数求和后除1000乘公里价；起送串店按起送价加超出包含店数的串店价；共配逐票件数乘每件价。小计四舍五入到分后加总；0有效、空值不可用。不加地图收费，不乘车辆倍率，不返仓，不按件数推算重量。

实际到店=上店实际离店+当前路段耗时。开始卸货取到店与开门较晚值，最晚到店比较实际到店而非开始卸货；开门、闭店、最晚到店边界包含等号。允许关门前开始卸货、关门后卸完；跨日采用完整北京时间日期时间。

小规模子问题可使用候选顺序枚举与车辆池动态规划；有未知道路失败时不会证明全局最优。日常自动任务对同一冻结输入执行多轮、多个可复现种子和多种搜索策略，汇总当前任务的线路及完整方案，重新计价后用整数金额进行联合选优。几何近邻只帮助提出查询对象，不作为最终计费距离或时间。结果记录实际轮次、种子、候选及截断数、计算预算、停止原因、道路采集时间、缓存和真实调用数。有限候选池的最优不代表全部可能配送组合的全局最优；系统保存时限内已找到并验证的最低费用可行方案。人工调整可依用户选择增加费用。

独立复核再次检查任务恰好一次、整票件数、真实车辆至多一线、容量与可用性、同仓/完整报价、费用、逐店时序及证据摘要/车辆参数绑定。自动深度规划不会保存未完成或有阻塞冲突的新方案；人工调整产生的冲突仍需处理后才能确认。保存时再次核对当前快照、资料及方案版本，避免覆盖他人更新。

## 货车服务与地图

位置管理和真实轨迹展示使用高德地图。当前日常算路使用普通驾车参考；位置搜索、地图展示与道路规划各自按服务上限限流。

当前未开启付费货车路径规划。普通驾车的任务总调用次数可为无限制，继续遵守每秒3次共享限流；深度任务自身仍有计算、整体等待和候选搜索边界。货车调用受独立开关及 `SUKA_TRUCK_JOB_MAX_CALLS` 配置约束；最多两次尝试，重试计入实际调用数。服务端密钥不会进入前端、快照、导出、缓存键或错误信息。

货车适配器仅使用高德高级货车接口，发送实际车牌、车型、车长宽高、满载总重、核定载重、轴数及策略。请求证据/缓存键包含全部车辆参数（含车牌颜色）、出发时刻、坐标及坐标系、策略、来源和接口版本；按逐店离店时刻逐段查询，不截断长线路。缓存有时效，固定数据与真实数据隔离。

当前高级货车适配器未证明任意指定出发时刻、车牌颜色参数的完整限行语义；返回的当前耗时不能冒充未来发车耗时。适配器将其标为未核验并阻止专车确认。真实货车能力仍需后续独立验收：开通权限与调用授权、服务商确认满足时间和完整货车约束的接口能力、经过核实的GCJ02算路坐标、真实车牌及参数。0.15本轮真实调用为普通驾车接口，并非货车执行验证。WGS84/BD09位置展示转换不等于货车算路坐标已通过核验。

参考官方接口：[高级货车](https://developer.amap.com/api/logistic-service/guide/wagon_path/hc-route-plan)、[基础货车](https://developer.amap.com/api/logistic-service/guide/wagon_path/truck-route-plan-basis)、[未来货车ETD](https://lbs.amap.com/api/webservice/guide/logistics-api/routeplan)。

## 新增接口

均要求登录，写操作还要求CSRF与来源校验。

| 接口 | 用途 |
| --- | --- |
| `GET /api/planning/capabilities` | 配置与调用开关、默认300秒、自动深度流程及复核能力，不返回密钥 |
| `POST /api/planning/jobs` | OPTIMIZE从当前分组快照执行完整深度流程，MANUAL提交人工选择重算；要求expected_head |
| `GET /api/planning/jobs/{id}` | 任务状态、阶段与轮次进度、错误、结果版本和计算摘要 |
| `POST /api/planning/jobs/{id}/cancel` | 请求取消；外部请求有超时后返回 |
| `GET /api/planning/days/{date}/jobs` | 最近20个任务，刷新后恢复查看 |
| `GET /api/planning/days/{date}/plans` | 分页读取只读历史版本 |
| `GET /api/planning/plans/{id}` | 冻结输入与结果，动态标记输入是否变化 |
| `POST /api/planning/plans/{id}/confirm` | 复核最新且当前输入的方案，追加确认版 |
| `POST /api/planning/plans/{id}/restore` | 按当前head恢复历史内容为新草稿 |
| `GET /api/planning/plans/{id}/export.xlsx` | 六表Excel |
| `GET /api/planning/plans/{id}/export.json` | 完整证据JSON |
| `GET /api/planning/examples/{MIXED_56或SHARED_40}` | 隔离固定样例 |
| `POST /api/planning/examples/{id}/recalculate` | 隔离人工演练，不能确认执行 |

后台任务在数据库持久化，运行时不持有全局写锁；短事务认领，提交时再次核对方案head，冲突不会覆盖。队列可在重启后继续认领；进程突然中断的RUNNING任务在租约到期后标记WORKER_INTERRUPTED，保留原快照供重新运行，不伪装完成。
