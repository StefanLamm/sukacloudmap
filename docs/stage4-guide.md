# 第四阶段：每日需求导入与规划输入（v0.4.0）

第四阶段已实现每日配送需求上传、列匹配、逐行校验、重复汇总、整日替换、来源追溯，以及不可变规划输入快照。全部业务操作在「物流线路规划」中完成，仓库、门店、车辆、报价管理继续只维护基础资料。

## 日常使用

1. 先维护仓库、门店、车辆和报价。进入「物流线路规划」，选择配送日期。
2. 在「仓库与车辆安排」核对当天最早发车、归仓及可用性。
3. 在「每日需求与快照」下载模板，填写门店名称、件数，必要时补门店编号。
4. 点击「导入当日需求」上传xlsx。确认名称列、件数列和可选编号列，可展开文件前几行核对。重复或无法识别的表头不会自动猜列。
5. 点击「校验并预览」。查看错误来源行、重复汇总、零行跳过、各仓统计及替换前后变化。
6. 只有全部通过后，才能勾选带明确配送日期的确认项，替换当日需求。确认会同时保存一份输入快照，任何中途失败都整体回滚。
7. 需求明细可查看原文件行，或设置门店「收货限制」。调整资料、发车、归仓、可用性或收货限制后，旧输入会显示已变更，点击「重新冻结输入」保存新版。
8. 在「历史快照」查看旧版，或下载只读输入JSON。旧版内容不从当前主资料重新拼装。

「门店与报价校验」只显示所选日期的正件数需求门店，零件数门店不进入业务任务。业务筛选、地图和兼容判断沿用已实现的功能。

## 文件与匹配规则

- 模板包含门店名称、件数和可选门店编号；配送日期只在页面选择，不从文件猜测。
- 首行必须是文字表头，数字或日期表头会拒绝，避免误丢首条需求。标准名称可自动建议列，其他表头可手工指定。同一列不能映射到两个字段，名称列和件数列必须明确选择。
- 提供编号时优先按稳定编号匹配，编号必须是文本，保留 `0001` 等前导零。编号去首尾空白并转大写。若同时填写名称，名称必须与编号对应门店一致；未知编号不会回退成名称匹配。
- 未提供编号时，名称去首尾空白后必须精确、唯一匹配。重名、未知或空名称都报错；已提供有效编号的行允许名称留空。
- 件数为非负整数；布尔值、空值、负数、小数及无效文本报错。Excel数值2.0是整数2，文本 `2.0` 不作为整数猜测。单行上限为1000000000。
- 同一门店的正件数重复行相加，保留每条来源行及件数。零件数行在批次中保留但不生成任务，空行跳过；零件数行也需要合法门店。
- 任意错误阻止整批提交。缺位置、报价或货车参数作为配置提示，不能冒充免费或道路已验证，但不阻止需求本身入库。
- 完全无数据行的文件不能提交。全部合法行均为零时，可以明确确认将当日任务清空，并保存零任务输入版本。

一次确认替换所选配送日的**全部仓库**需求，不受页面仓库筛选影响，也不会与前次导入累加。再次上传同样件数仍保留同样总数，但会记录新的需求修订和来源批次。重复点击同一个已提交批次只返回原回执，不会回放旧数据覆盖新需求。

同一文件先预览后再修改列映射，会得到新的预览修订。提交需要配送日期和预览修订同时匹配。预览期间若基础资料、该日资源或该日需求变化，需要重新预览；其他日期的安排和账号编辑不会误使预览失效。上传及预览有效24小时。

每个文件最多5MiB、10000个非空数据行，另有解压体积、列数和稀疏工作表保护。超过限制时应先清理格式或汇总重复行；不要把同日需求拆成多个文件逐次确认，因为每次确认都会整日替换。仅接受xlsx，不接受公式、错误单元格、宏及外部链接。

## 当日收货限制

当天最晚到店默认采用门店营业结束时间，列表标注「随营业结束」。同日闭店取配送当日，次日闭店按明确跨日设置取配送次日，例如2026-11-12配送、次日02:00闭店，对应2026-11-13 02:00。修改门店营业结束时间后，当前未单独限制的需求自动跟随，新冻结输入采用新时间。

有特殊要求时，在当日需求行点击「收货限制」，按北京时间填写配送当日或次日的最晚实际到店时间；留空或点击「按营业结束时间」恢复默认。每个配送日独立保存，使用自己的修订号，不修改门店管理中的默认资料。

为兼容旧资料，旧版门店最晚到店仅在其日期属于所选配送日或次日时沿用；其他日期自动采用闭店时间。当天显式清空可覆盖旧值并恢复跟随闭店时间。营业时间仍来自门店固定资料，冻结时按配送日和明确跨日标记生成完整的开、闭店日期时间；卸货时长原样冻结。需求明细、输入快照和算路使用同一个最晚到店值；历史快照保持原内容，规则或营业时间变化后需重新冻结。实际行驶、等待与到店可行性在S5验证。

## 快照包含什么

每个配送日期的输入版本从V1递增，保存后不提供修改或删除接口。相同输入重复冻结返回原版本；需求重传、主资料或当天输入变更后冻结会新建版本。

| 内容 | 冻结值 |
| --- | --- |
| 需求 | 每票稳定门店ID、件数、仓库、来源行、原始名称/编号、批次ID及文件摘要 |
| 门店 | 地址、坐标及来源、经营时间、跨日日期、卸货时长、最晚到店、报价引用和精确单价 |
| 仓库 | 所有仓库资料、默认与当日修订、带日期的北京时间最早发车；无需求仓也保留且统计为0 |
| 车辆 | 所有真实车辆记录、按日归仓/可用性、最大件数、货车参数、默认与当日修订 |
| 报价 | 需求门店在该日生效的完整报价版本及参数签名；NULL与0保留区别 |
| 依据 | 时间区、单位、需求修订、主资料与当日修订摘要、规范化SHA-256内容哈希、操作者与时间 |

快照保存具体使用值，不只保留指向可变主资料的外键。后续门店换仓、改名、改价、车辆变化和再次导入都不会回写旧快照。当前状态提示通过比较当前输入指纹得出，不修改历史内容。即使件数未变，只要来源批次或修订改变，旧输入也会提示需更新。

内容哈希对 `input` 对象进行UTF-8 JSON编码：键按字典序、无多余空白、中文不转义、不允许NaN，再计算SHA-256。读取/导出快照时验证内容哈希，完整性失败会拒绝使用。JSON外层的「输入是否已变化」是读取时的状态，不是冻结正文的一部分。

本阶段尚未生成配送线路，因此对旧方案的提示基础是「方案绑定的输入快照是否变化」。后续S5/S6/S7必须绑定快照ID和内容哈希，不能用当前主资料覆盖已保存的输入；真实道路结果需另存道路证据，不得把本阶段的 `NOT_VERIFIED` 当成通行验证。

## 接口

所有接口均在 `/api/planning` 下，要求登录，写请求要求现有CSRF令牌。普通业务账号与管理员共享同一套业务数据。

| 方法与路径 | 行为 |
| --- | --- |
| `GET /demand-template.xlsx` | 下载每日模板 |
| `POST /demand-imports/upload?delivery_date=2026-11-11&filename=daily.xlsx` | 请求体直接传xlsx字节，受限上传后重新认证并读取列 |
| `GET /demand-imports/{id}` | 获取列、样例行、映射、预览及回执 |
| `POST /demand-imports/{id}/preview` | JSON列索引：`store_name`、`pieces`必填，`store_code`可空；从0开始 |
| `POST /demand-imports/{id}/commit` | JSON明确 `delivery_date` 和 `preview_revision`，事务替换并自动冻结 |
| `GET /days/{date}` | 当前需求、各仓统计、输入指纹及最新快照状态 |
| `PUT /days/{date}/stores/{id}` | `latest_arrival_at`（含时区或NULL）、`expected_revision`，保存当日限制 |
| `POST /days/{date}/snapshots` | `expected_revision`、`expected_fingerprint`，冻结当前输入 |
| `GET /days/{date}/snapshots?offset=0&limit=20` | 分页读取历史元数据与输入变化提示 |
| `GET /snapshots/{id}` | 读取并校验完整冻结内容 |
| `GET /snapshots/{id}/export.json` | 下载JSON输入，内容与查看版本一致 |

未知/重名、件数和文件错误返回422；过期、旧预览、输入指纹及修订冲突返回409。错误时保留当前输入，预览可重新计算，不进行部分需求更新。快照存储完整性失败返回500并拒绝使用。

## 迁移、验证与后续

`0003_daily_inputs`从`0002_master_data`增加每日需求、来源批次、当日收货限制和快照表。没有删除或重建旧主资料表。启动脚本会执行迁移；服务启动本身只检查版本。

本轮升级前已为本地SQLite保存独立备份，并验证旧记录ID保留。备份路径记录在 `stage4-workspace-evidence.json`，该文件与业务库同属本地受保护资料，不提交或对外分享。历史备份恢复后需要重新执行迁移才能启动新版程序。

运行验证：

```bash
.venv/bin/python -m pytest -q
./scripts/build-frontend.sh
.venv/bin/python scripts/verify_live_restart.py
```

结果见 `stage4-validation.json`。4仓800店24000件50车固定集仅验证导入、来源、统计及输入冻结，不是排线性能、费用或真实道路验收。PostgreSQL仍待目标环境联调。

仓库无需求、车辆不足、缺报价等信息都会保留，S5/S6负责据此计算方式限制与异常，不在S4自动分车或拆票。下一阶段为货车道路与计费时序。

附带的 `examples/daily-demand-template.xlsx` 是空模板；`examples/stage4-frozen-input-example.json` 是独立临时测试数据的只读样例，不会植入业务库。
