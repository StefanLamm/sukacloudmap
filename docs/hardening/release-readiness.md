## 真实数据与采用的配置

源目录为相邻的「物流分析表」，仅只读提取五份登记表；源路径、SHA256、逐日件数及归仓依据见 [source-analysis.json](source-analysis.json)。原始共12185行、241806件、150日。按用户指定的“安徽归合肥、江苏归淮安”可明确归仓11921源行，合并同店同日两处重复后11919票，共234690件。其余264行7116件、涉及43个名称，外省归仓或城市信息待确认，逐行列于 [data-gaps.json](data-gaps.json)，没有默认塞进两仓。

按用户确认设置专车5.8元/公里，每车400件，仓库文字位置在两市市政府。共配等同拼车；承运每件成本仍空缺，没有把收入当成本，也没有将重复填写的整段支出累加成每店报价。2026-11-12增补：用户已确认历史支出按“日期＋车牌”取来源首行，金额不同也取首行，逗号按小数点解析；已完成19项专项测试和五份原表独立复核，见 [历史费用核对](historical-cost-review.md)。该口径用于历史整车支出控制，不自动转换为未来拼车每件价。

50个UAT车位分配合肥35、淮安15，车牌为测试号；08:00–23:59营业、卸货5分钟为测试假设。4.2米级参考冷藏车尺寸5.995×2.35×3.35米、总重4.495吨、额定载重1.09吨等只作测试参考，每辆实车尚需核验。[车型供应商参考](https://www.cnclzg.com/prodview183.html)不能替代实车证件；两轴、蓝牌等通行字段同样为待核验参数。仓库位置采用文字地址，未伪造仓库或门店坐标。

## 待完成的验收

1. 用户回来后完成普通浏览器人工复核与调整：登录、文件选择、地图拖拽和保存、离开确认的继续/放弃、人工改序、版本恢复和导出。遗留原生弹窗阻塞了本轮内嵌浏览器；代码已修复、组件已通过，但无法把最终实机操作标记为通过。当前用户不在电脑前，无需立即操作。[页面证据](../screenshots/hardening-real-demand.png)仅说明已经显示的需求和测试标识。
2. 补齐拼车成本单价、264行待归仓记录、门店精确定位/收货时间及真实车辆证件参数。当前缺失项保持显式异常，不能用模拟结果承诺实际配送。
3. 核验地图外部服务可达性。本轮命令行对Photon公开市政府查询返回403，见 [搜索检查](warehouse-geocode.json)；未绕过限制或填写猜测坐标。代码保留失败提示及手动坐标/地图拖拽，搜索和瓦片仍需在实际网络实机复核。
4. 按之前约定稍后配置真实货车接口，核验指定发车时间、坐标系、限行语义、真实道路及调用额度，再验收执行确认。当前不满足条件的专车方案仍阻止确认；测试道路版本始终不能确认。
5. 正式部署环境待提供；PostgreSQL真库、HTTPS/反向代理、多进程负载和目标备份恢复需在该环境验证。当前结论只覆盖本机SQLite。

后端有一条FastAPI/Starlette测试客户端的httpx弃用提示，全部测试通过；属于测试依赖迁移提醒，非本轮功能失败。没有为消除提醒而更换已固定的运行依赖。
