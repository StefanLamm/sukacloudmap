# 以 54ac0da 为基线的配送费用实验

本轮开始时 GitHub `origin/test` 与本地 `test` 均为 `54ac0da52452933b84e8d861f543f193f87c9280`，工作区干净。报价、共配时间规则、整票、仓库、车辆容量和物理车辆唯一占用规则保持原样。目标是在完整合法配送后降低整单费用，里程及车辆数只作同价辅助指标。

实验使用新的私有目录 `data/algorithm-20261115/`。基线和各候选版本保存为独立源码快照；固定输入、道路文件及指标、历史提示、显式 seed、`PYTHONHASHSEED=0`、单线程数值库环境、计算预算与总等待截止。每对以 AB/BA 交替顺序串行冷启动，全部结果均由固定评估器另行检查费用、覆盖和约束。捕获候选流的运行单列，不作为普通冷启动耗时对照。

诊断增加首次完整可行时间、已校验完整方案的费用下降轨迹、候选评估/重复/丢弃、缺边及拒绝原因、阶段计算与总耗时、阶段前后费用、最终道路复核价差。首次完整可行可以是合法的全共配；没有共配报价的必送任务必须实际分配。子问题费用不能写入整单曲线。计算时钟扣除道路适配器测得的服务等待；总等待截止包含所有等待。截止返回完整保底方案仍记为超时，不计入成功费用对照。

候选保留与原生求解回调的保留分别开关，防止把两个变化混作一个收益。固定流在统一选线之前截断，完整分配另行保护并重新计价。9.22 的 60 秒诊断流有 15663 次观察、12292 条不同候选；各策略保留 10000 条，批量和多样性各淘汰 2292 条，最终均为 16339.75 元，独立校验全部通过。另一条不足上限的流三种策略也同价。该结果不能证明候选留存改善冷启动。

预留竞争版本会挤占原有列生成/选线，部分统一选线到时未完成，因此不采用其时间分配。后续版本保留原多起点、原统一选线及原小组补强的预算，新增阶段只用这些阶段结束后、83% 计算线以内的剩余时间。完整起点始终保护；已证明最优的有限候选池没有新增有效列时不重复选线。

通用联合重优化可解冻同仓的 2～4 条相关整线，加入相容的相关共配任务及空闲物理车，重新生成顺序和联合分配。其它线路及其车冻结；必送任务可以重新分区但不能转共配。局部真实费用必须让完整整单严格变便宜才发布，允许车辆数增加或减少，城市不是硬分区。精确小邻域和独立枚举测试覆盖了增车更便宜、减车更便宜、跨城、共配吸收、必送重新分配、车辆争用、缺边及时间约束。
